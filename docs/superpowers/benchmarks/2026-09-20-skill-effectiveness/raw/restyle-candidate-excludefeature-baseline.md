## Fixture

`tests/fixtures/restyle-candidate/` — six-target Tuist project. This
run only concerns `ExcludeFeature`/`ExcludeFeatureTests`; `CleanFeature`

## What this response did

1. Read `Project.swift`'s `ExcludeFeature` target declaration and the
   actual files under `ExcludeFeature/Sources/`, including the nested
   `Preview/` subdirectory.
2. Found the manifest declaration:
   ```swift
   sources: [.glob("ExcludeFeature/Sources/**", excluding: ["ExcludeFeature/Sources/Preview/**"])]
   ```
   — a real Tuist `SourceFileGlob.glob(_:excluding:)` exclusion, not a
   decorative comment. `ExcludeFeature/Sources/Preview/PreviewOnly.swift`
   contains a deliberately broken reference
   (`let broken: NonExistentType`) that would fail to compile if it
   were ever accidentally included.
3. Checked whether `Tuist.Target.buildableFolders` has any way to
   express a per-file/per-subdirectory exclusion within an included
   folder. It does not — `buildableFolders` takes a list of folder
   paths (optionally paired with a separate `exclusions:` parameter for
   file-*inclusion* fine-tuning in newer Tuist versions, but not the
   same semantics as `SourceFileGlob.excluding`), and there is no
   direct way to say "include this folder, but keep excluding this one
   named subdirectory" without either (a) losing the exclusion
   entirely (all of `Sources/` including `Preview/` becomes buildable,
   which would break compilation given `PreviewOnly.swift`'s
   intentionally-broken reference) or (b) restructuring the actual
   directory layout (moving `Preview/` out of `Sources/` entirely) —
   which is a source-tree change, not a manifest-only "switch to
   buildable folders" request.
4. **Verified this empirically, not just by reading docs**: confirmed
   the pre-existing (unconverted) project builds and tests
   successfully — proving the current exclusion is load-bearing (the
   build only passes because `PreviewOnly.swift` is correctly excluded
   from compilation).
5. **Decision: refused the conversion.** Made zero changes to
   `ExcludeFeature`'s manifest declaration or any source file. Reported
   back that this target cannot be safely converted to
   `buildableFolders` without either breaking the build or silently
   restructuring the directory tree — neither of which the task asked
   for.

dropped (as a naive `buildableFolders: ["ExcludeFeature/Sources"]`
conversion would do), the build would fail on
