## Task prompt

> Migrate this project's Tuist manifests from 3.42.2 to 4.206.0.

## Fixture

`tests/fixtures/migrate-candidate/` — single-target Tuist project
(`App` + `AppTests`), starting on Tuist 3.42.2 with `Tuist/Config.swift`
and `Project.swift`'s legacy `Target(name:platform:product:bundleId:
deploymentTarget:infoPlist:sources:...)` member-wise initializer.

## What this response did

1. **Verified the starting state is real** before touching anything:
   ran `tuist generate --no-open` under 3.42.2 (succeeded) and under
   4.206.0 (failed, with the exact cascade of "extra arguments" /
   "cannot infer contextual base" errors that follow from `Target`'s
   3.x initializer no longer existing in 4.x — 4.x's `Target` struct
   only exposes `init(from: Decoder)`).
2. Renamed `Tuist/Config.swift` → `Tuist/Tuist.swift` via `git mv`, and
   replaced `let config = Config(generationOptions: .options())` with
   `let tuist = Tuist()`.
3. Rewrote both `Target(...)` call sites in `Project.swift` to the
   `.target(...)` static factory: `platform: .iOS` → `destinations:
   .iOS`; singular `deploymentTarget: .iOS(targetVersion: "17.0",
   devices: [.iphone])` → plural `deploymentTargets: .iOS("17.0")`.
   Left `product:`, `bundleId:`, `infoPlist:`, `sources:`, and
   `dependencies:` unchanged — those parameter names/shapes carried
   over from 3.x to 4.x without change.
4. Left `App/Sources/MigrateCandidateApp.swift` and
   `App/Tests/AppTests.swift` byte-identical — no source-level
   breaking change exists in this jump, only manifest-level.
5. Did **not** touch any file outside this fixture directory (e.g. no
   attempt to locate or edit an outer CI matrix/version-pin file
   referencing this fixture — out of scope for "migrate this project's
   manifests").
