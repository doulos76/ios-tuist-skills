## Task prompt

> Add a scaffold template that generates a labeled-enum Swift file from a name.

## Fixture

`tests/fixtures/scaffold-candidate/` (committed state: two targets,
`App`/`AppTests`, plus an already-committed `tuist scaffold` template at
`Tuist/Templates/feature/` — `feature.swift` + `source.stencil` —
which happens to generate the exact same shape the prompt describes).

## What this response did

- Inspected `Project.swift` (`App`/`AppTests`, no feature modules) and
  the existing `Tuist/Templates/feature/` directory before writing
  anything, to understand the project's existing scaffold-template
  convention:
  - `feature.swift` declares `let nameAttribute: Template.Attribute =
    .required("name")` and a `Template(description:attributes:items:)`
    with one `.file(path: "Sources/\(nameAttribute)Label.swift",
    templatePath: "source.stencil")` item — the `path:` interpolates
    the attribute with plain Swift string interpolation, not
    Stencil-style `{{ }}` tags (those are reserved for the template
    *body*, rendered by the Stencil engine against `source.stencil`).
  - `source.stencil` is a one-line Stencil file:
    `public enum {{ name }}Label { public static let text = "{{ name
    }}" }` (formatted across three lines in the fixture).
- Recognized that this existing `feature/` template already produces
  exactly the labeled-enum shape the prompt asks for, but treated the
  prompt as a request to **add** a new, general-purpose template
  capability (not to point at or rename the existing one) — created a
  **new**, separately-named template, `Tuist/Templates/labeled-enum/`,
  rather than editing or duplicating-in-place the existing `feature/`
  template. Did not touch any file under `Tuist/Templates/feature/`.
- Authored `Tuist/Templates/labeled-enum/labeled-enum.swift`:
  ```swift
  import ProjectDescription

  let nameAttribute: Template.Attribute = .required("name")

  let template = Template(
      description: "Generates a single Swift source file declaring a "
          + "public enum named <name>Label with a static text property.",
      attributes: [
          nameAttribute
      ],
      items: [
          .file(
              path: "Sources/\(nameAttribute)Label.swift",
              templatePath: "source.stencil"
          )
      ]
  )
  ```
- Authored `Tuist/Templates/labeled-enum/source.stencil`:
  ```stencil
  public enum {{ name }}Label {
      public static let text = "{{ name }}"
  }
  ```
- Basis for this syntax: general knowledge of Tuist's `tuist scaffold`
  feature — a `Template` manifest per subdirectory of
  `Tuist/Templates/`, `Template.Attribute.required`/`.optional` for
  parameters, `Template.Item.file`/`.directory`/`.string` for outputs,
  and Stencil templating (`{{ name }}`) for file bodies, with the
  manifest's own `path:` argument using ordinary Swift string
  interpolation of the attribute rather than Stencil syntax (since
  `path:` is evaluated in Swift when the manifest is parsed, before any
  Stencil rendering happens). This is general framework knowledge, not
  something inferred from reading `Tuist/Templates/feature/` beyond
  confirming the shape looked right — the two templates ended up
  structurally identical because the prompt's requested shape and the
  existing example's shape are, in fact, the same thing.
