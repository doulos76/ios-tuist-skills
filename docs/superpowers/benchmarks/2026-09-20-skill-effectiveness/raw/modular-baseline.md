### Root cause investigated, not just reported blind

Checked the vendored dependency's own manifest:

```
$ cat Tuist/.build/checkouts/Kingfisher/Package.swift | head -8
// swift-tools-version:5.1
import PackageDescription

let package = Package(
    name: "Kingfisher",
    platforms: [.iOS(.v13), .macOS(.v10_15), .tvOS(.v13), .watchOS(.v6)],
    ...
```

```
$ xcodebuild -version
Xcode 27.0
Build version 27A266a

$ xcodebuild -showsdks | grep iphonesimulator
	Simulator - iOS 27.0          	-sdk iphonesimulator27.0
```

Kingfisher 8.12.0's own SPM manifest declares `.iOS(.v13)` as its
platform floor. This Xcode 27 toolchain's iOS Simulator SDK only
supports deployment targets **15.0 and above** — a real,
environment-specific ceiling on old deployment targets, unrelated to
Tuist. One remediation attempt was tried and **did not** fix it: adding
an explicit `platforms: [.iOS(.v17)]` to this project's own
`Tuist/Package.swift` — this had no effect, because that field
constrains the *consuming* package's own platform declaration, not a
transitive dependency's (Kingfisher's) own manifest, which Tuist honors
as-is when generating Kingfisher's own derived Xcode project. That
change was reverted after confirming it didn't help (kept the diff
honest — see below).

This is a real, reproducible incompatibility between this specific
Kingfisher release and this specific Xcode toolchain's minimum
supported deployment target — not a fixable "same-target" wiring
mistake. A production fix would require either pinning to an older
Xcode, waiting for/selecting a Kingfisher release whose manifest raises
its floor, or (out of scope for "add Kingfisher to ProfileFeature")
patching the dependency itself.
