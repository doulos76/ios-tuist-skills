## Fixture

## What this response did

1. Read `Project.swift`'s `CleanFeature` target declaration and the
   actual files under `CleanFeature/Sources/` and
   `CleanFeature/Resources/` before deciding anything.
2. Found: plain `sources: ["CleanFeature/Sources/**"]` and `resources:
   ["CleanFeature/Resources/**"]`, no exclude globs, no per-file
   attributes, no other target referencing an individual file inside
   either directory (only whole-target dependencies from `App` and
   `CleanFeatureTests`), and no directory overlap with any other
   target's source/resource/buildableFolders paths.
3. Judged this safe to convert — a plain recursive glob over a
   self-contained directory tree is exactly what `buildableFolders`
   was designed to replace.
4. Applied the conversion in `Project.swift`:
   ```diff
   -            sources: ["CleanFeature/Sources/**"],
   -            resources: ["CleanFeature/Resources/**"]
   +            buildableFolders: ["CleanFeature/Sources", "CleanFeature/Resources"]
   ```
5. Left `CleanFeatureTests`, `ExcludeFeature`, `ExcludeFeatureTests`,
   `App`, and `AppTests` manifest declarations untouched — not named in
   the request.
6. **Flagged a residual risk rather than a clean pass:** `CleanFeature`
   is a `.staticFramework` product that also declares resources — a
   combination that has had real Tuist resource-bundling regressions in
   the past (bundle contents/placement, not generate/build failures).
   This response verified live that generate/build/test succeed for
   this specific fixture and that the resource bundle
   (`RestyleCandidate_CleanFeature.bundle`) is produced and contains
   `dummy.txt` — but noted that a clean local test pass does not by
   itself retire that category of risk for other projects/Tuist
   versions, so it reported the conversion as done-with-a-noted-
   residual-risk rather than an unconditional "safe, done."
